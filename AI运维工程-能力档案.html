02 · POSITION项目定位

企业私有化 AI 应用的交付与运维工程：覆盖应用部署（测试单机 / 生产集群）、中间件离线交付（搜索引擎 / 缓存 / 国产分布式数据库）、运维知识库与验收闭环——目标是「照单部署、不迷路」。

这不是一份部署文档，而是一套由 AI 智能体团队持续运转的交付体系——每一个交付物背后都有规划、门控、留痕与验收。

03 · METHODOLOGY工程方法论

贯穿整个工程的方法论——由 AI 智能体团队执行、沉淀、复用。

M-01

Harness 团队驱动

多编排器分工（部署工程 / 问题分流 / 开发）+ 多智能体角色（架构师 / 脚本工程师 / 日志专家 / QA / 验收工程师）。请求先分类、再走对应流水线，禁止绕过编排直接动手。

M-02

流水线门控

规划 → 实现 → 验证 → 验收，每一阶段设置质量门；产物落工作区、可复查，QA 门控不通过不进入下一阶段。

M-03

全链路留痕

服务器与容器操作强制逐条留痕（命令 + 返回 + 解读），「盲盒日志」机制保障无现场可视化时的排障闭环——行为可回溯，问题可定位。

M-04

离线交付思维

中间件封装为「一键部署 + 一键验收 + 一键打包」三件套：内网可导入、可运行、可核对——信创环境的工程化答案。

M-05

知识沉淀

避坑知识库、运维手册、容量规划、上线核对清单——把个人踩坑经验沉淀为组织可复用的知识资产。

M-06

一致性治理

跨文档冲突按既有裁决优先级执行，禁止「协商解决」——把工程规范变成可执行、可校验的硬规则。

04 · AI CAPABILITYAI 与 LLM 能力层

本工程以大模型能力为底座，构建面向运维场景的智能体体系，LLM 贯穿工程执行与运维决策的多个环节：

  • 智能体编排LLM 驱动的多智能体团队（分析 / 设计 / 实现 / 验证 / 验收），按领域编排器分工协作，自主完成从需求到交付物的全流程。
  • 智能排障与语义分析结合日志留痕机制，对故障信息进行语义级理解与归类，辅助定位问题根因，形成排障闭环。
  • 运维知识问答基于运维手册与避坑知识库的知识底座，支持以自然语言获取部署指引、核对事项与处置建议。
  • 方案与文档生成由智能体按统一规范生成部署方案、运维文档、验收报告，内容口径一致、可直接执行。
  • 模型无关设计能力层走兼容协议接入，模型可替换、可离线，不绑定单一厂商，适配内网与信创环境约束。

AI 工程化组织多 Agent 编排LLM 集成信创交付中间件交付容器化部署 K8s 集群镜像治理留痕审计知识库建设验收体系
