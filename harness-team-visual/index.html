02 · USE SCENARIO使用场景

SC-01

赋能谁

需要把 AI 从「单次对话」升级为「常驻团队成员」的开发者与研发团队——项目越复杂、越需要项目级上下文，价值越大。

SC-02

什么场景

项目复杂、需求多变，每次开新会话都要重新解释项目；AI 没有项目上下文，产出不连贯、边界靠猜。

SC-03

解决什么

用 9 步方法论 + 搭建/派单工具 + 垂直团队实例，为任意项目搭建可被真正调度的多 Agent 团队：角色、路由、技能、知识库一次配齐。

SC-04

带来什么

一句话需求经多层过滤产出准确结果；成员帮你想没想过的边界；团队随项目沉淀知识、持续演进。

04 · METHOD团队组建 · 9 步流程

S-01

梳理指令

目标七问：目的 / 完成态 / 证据 / 反作弊 / 地界 / 取舍 / 未知——先想清楚再做。

S-02

探查项目

亲手跑一遍：读文档、看代码、查 git 状态、验证依赖可行性，不照抄文档。

S-03

分析现状

目标是什么、已完成什么、还缺什么——按严重度排序，区分逻辑缺口与交付缺口。

S-04

设计班子

6 种模式选型（可混合）：流水线 / 扇出扇入 / 专家池 / 生产者-审校者 / 监督者 / 层级委派。

S-05

落盘配置

把角色、职责、路由触发词落成团队配置文件，能被指令真正调度。

S-06

路由表

定义触发词 → 角色的路由规则，让请求自动分流到正确的团队成员。

S-07

装大脑

为团队配置技能与知识入口，成员具备完成任务的领域能力。

S-08

知识蒸馏

把项目经验蒸馏为可复用知识，沉淀为团队资产。

S-09

知识库整合

整合知识库与版本管理，团队随项目持续演进，git 提交收尾。

05 · PATTERNS6 种协作模式

P-01

流水线

阶段串行、门控推进——适合确定性交付链路。

P-02

扇出扇入

任务并行分发、结果汇合——适合可拆分的独立子任务。

P-03

专家池

按领域调用专家成员——适合跨领域综合任务。

P-04

生产者-审校者

生产与审校分离——适合内容与代码质量把关。

P-05

监督者

主成员监督分派、整合交付——适合复杂多线任务。

P-06

层级委派

多层代理逐级拆解——适合大而复杂的组织型任务。
